# 项目群聊

官方群聊容量：**2～6 个 Bot**。核心编制用 4 个：项目经理、开发、测试、评审。

## 建群

1. 侧栏 New → 勾选这 4 个 Bot（可选再加调研、发布，总数 ≤ 6）。
2. 把群名改成「交付：<产品或仓库短名>」。
3. 把下面开工词整段贴进去。
4. 之后你只派新活、拍板合入；日常交接让他们 `@` 彼此。

## 开工词（粘贴到群）

```
这个群只做一件事：把当前工作变成可审查的交付，并在合入/发布前停住。

规则：
1. 每个阶段一个 owner。没有 @ 时，由项目经理认领或指定。
2. @开发 实现，停在草稿 PR / 可审查 diff，不合入。
3. @测试 用独立证据验收（复现包或回归记录）。测试不得补实现。
4. @评审 只列出阻断项，不改代码「顺便修」。
5. 发送、付款、删除、改生产、合入：必须 @我 并等批准。
6. 不要 @everyone 报日常进度。阻塞超过自己无法处理时才 @我。

@项目经理 根据我下一条消息拆成任务表：编号、owner、完成定义、是否阻塞。不要自己写代码或测。
```

把「下一条消息」换成真实需求，例如：「把登录失败提示改成可访问的文案，并补回归」。

## 频道六条（可放群置顶 / 话题）

1. **所有权**：项目经理维护任务表；开发写；测试验；评审找阻断；我合入。
2. **节奏**：有实质进展再发言；不要每人一段日报。
3. **何时 @我**：需要合入、发外、密钥、生产、范围变更、或两个岗位结论冲突。
4. **何时不要 @我**：常规交接、要源链接、要截图补证据。
5. **文件**：共享电脑上 `/workspace/handoff/<项目>/` 由项目经理建目录；开发写 `impl/`，测试写 `qa/`，评审写 `review/`。禁止两人同时改同一文件。
6. **编制**：不加第 7 个 Bot。缺能力先复用现有岗位，或 Duplicate 后再改范围。

## 站会（可选，由项目经理一条例程收集）

每个工作日，项目经理在群里贴一张表，每行三个字段：完成 / 阻塞 / 需要人。

- 其他 Bot **不要**各自再开例程报站会（费用量、刷屏）。
- 站会 **不得**自动派新活。新活只由你说。
