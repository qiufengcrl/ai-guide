# Skill 与 Routine

官方顺序：**先做一次真任务 → 改到可审查 → 存成 Skill → 换输入再测 → 再开 Routine。**

Skill = 怎么做。Routine = **哪个 Bot、何时**做。Skill 账号内可共用；例程挂在某一个 Bot 上。删 Bot 会删掉它的例程。

## 什么时候还不要开例程

- 还没在第二份真实输入上跑通
- 失败时会拿旧数据充数
- 例程会发送、合入、改生产
- 六个 Bot 各开一条日报（改成项目经理收集一次）

## 例程模板（对拥有该工作的 Bot 说）

把方括号换成你的时区、群名、来源。

### 项目经理：工作日站会收集

```
每个工作日 09:30（[时区]）在群「交付：[名称]」贴一张站会表。
向编制询问或根据可见交接填写：完成 / 阻塞 / 需要人。
不要派新任务。不要 @everyone。
来源不可用就报告失败，不要沿用昨天的表。
```

### 测试：含 “needs repro” 的工单（事件触发，若已接 GitHub/Slack）

```
当 [频道或工单源] 出现带预发链接且含 “needs repro” 的条目时：
在预发用测试账号做复现包，发回本对话。
不要回帖到 Slack/GitHub，除非我批准。
不要用生产客户数据。
匹配规则要窄，不要监听「每一条新消息」。
```

### 评审：PR 打开时出审查包（可选）

```
当指定仓库打开 PR 且描述中含「ready-for-review」时：
对照完成定义与测试证据写阻断项清单，发回本对话。
不要评论到 GitHub，除非我批准。
不要合入。没有测试证据则结论为无法审查。
```

## 启用前用 Test run

Test run **会做真事**（开会话、改文件、调连接器）。用安全输入，写入类动作保持审批。检查：

- 用的是当前输入，不是记忆里的旧表
- 输出格式对
- 每条动作有来源
- 停在预定审批点
- 失败状态写得明白

## 用量

例程在笔记本合上时也会跑。长期离开时应用可能询问是否暂停例程。回来后检查被暂停的条目。定价以 [Plans and billing](https://cursor.com/docs/grok-bot) 为准，不要用过期的座位价格做编制规模依据。
